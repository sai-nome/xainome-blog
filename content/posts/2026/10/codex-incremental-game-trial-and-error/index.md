このブログでも遊べるゲームを作ってみたいと思い、Codexを使ってインクリメントゲームを作ってみました。

インクリメントゲームは、クリックや自動生産でお金などを増やし、設備を購入・強化して、さらに生産量を増やしていくようなゲームです。少しずつ数字が増え、できることが広がっていくのが楽しいジャンルですね。

今回作ったのは、AI企業を育てる「AI Controler」というゲームです。最初は自分で案件をこなしてお金を稼ぎ、GPUやAIを導入して仕事を自動化します。そこから電力や冷却、研究、半導体の製造へと進み、最後はロケットの打ち上げを目指す形にしました。

[AI Controlerはこちらから遊べます]({{< ref "games/ai-controler/index.md" >}})。

実際に作ってみると、**ゲームの大枠を動かすところまでは進めやすいのですが、自分で遊んで「面白い」と感じるところまで持っていくのが大変でした。** そして、その調整をCodexにお願いするための言語化にも、思っていた以上に頭を使いました。

今回の制作で感じたことを先に挙げると、次の3つです。

- Codexを使うと、クリックや自動生産といったゲームの大枠を形にしやすかった。
- 面白いと感じるまでには、実際に遊びながら演出や設備のバランスを調整する必要があった。
- 「見やすくして」という感覚を、「文字を大きくする」「操作する場所を画像で示す」といった具体的な指示に変えるのが難しかった。


## ゲームの大枠はできた。でも、遊んでみると何か足りない

最初はChatGPTと相談しながらゲームの方向性を考え、それをもとにCodexにブラウザで動くゲームを作ってもらいました。

クリックするとお金が増え、そのお金でGPUを買うとAIが仕事をする。さらに設備や研究を増やしていく。こうした基本的な流れができて、ローカルで実際に遊べるようになりました。

自分が考えていたものを画面上で操作できるようになるのは、やはりうれしいですね。

{{< figure class="codex-game-screenshot" src="images/ai-controler-gameplay.png" alt="AI Controlerの初期画面。保有資金や計算能力、電力・冷却能力と、クリックで報酬を得る「案件をこなす」ボタンが表示されている" caption="AI Controlerのゲーム画面。まずは「案件をこなす」ボタンで資金を稼ぎ、GPUやAIの導入を目指します。" width="1018" height="735" align="center" link="images/ai-controler-gameplay.png" >}}


ただ、しばらく遊んでみると「悪くはないけれど、もう少し面白くしたい」という感じがありました。お金が増えて、設備が増える。それだけでもゲームとしては動いているのですが、何かを手に入れたときの喜びや、どんどん良くなっていくような爽快感が足りなかったんです。

そこで、実際に遊んで気になったところを、一つずつ調整していくことになりました。

## 効果音や購入演出を足して、手に入れた感じを出したい

まずお願いしたのは、効果音や文字の大きさの調整でした。

ボタンを押して数字だけが変わるよりも、音が鳴ったほうが操作した感じがあります。初めて設備やAIを手に入れたときには、そのアイテムを画面に出して、効果音と派手なエフェクトを付けてもらいました。

自分の中では、「初めて購入したときに、画面にアイテムを出してバーンと演出してほしい」というイメージです。

文字が小さくて読みづらい部分は、大きくしてもらいました。さらに、まったりしたSF風のBGMも流せるようにしました。

こうした部分はゲームの計算自体を大きく変えるものではありませんが、遊んでいるときの印象には関わってきます。ただ設備の所持数が一つ増えるよりも、「新しいものを手に入れた」と分かるほうが、次の購入も楽しみになりますね。

## 設備を増やすだけでは、成長の手応えにつながらない

音や見た目に加えて、ゲームの中身も調整していきました。

例えば、GPUを増やしていくときの電力や冷却のバランスです。GPUの数に対して必要な設備が少なすぎると、インフラを整える意味が薄く感じられました。反対に、設備を購入するお金との釣り合いが悪くても、進めにくくなります。

水や冷却の設備についても、作ったあとに高純度水や使用済み水の数字が増えるだけでは、何がよくなったのかが分かりにくかったです。

「この設備を作ると、何ができるようになるのか」「今までより、どこが改善されるのか」が見えないと、購入する楽しさにつながりにくいんですね。

そこで、設備の効果が分かるヘルプを追加したり、進行に応じて設備を段階的に表示したりしました。最初からすべてを見せるのではなく、今の自分に関係するものから順番に触れる形です。

自社GPUを研究ポイントで強化できるようにしたり、ロケットを最終目標にしたりと、先に進む理由も足していきました。

一度はクリック以外の稼ぎ方として簡単なパズルも追加しましたが、その後は削除してクリックに戻しました。パズルを解く手間が思ったよりも面倒で、報酬が増えても、クリックで稼ぐほうが楽に感じたからです。その代わり、お金を使ってクリック報酬やAIを強化できる形にしています。

作ってから遊んでみると、考えているときとは感じ方が違います。要素を追加することも、追加したものをやめることも含めて、試行錯誤が続きました。

## 「見やすくして」を、どこまで具体的に言えるか

こうした調整で大変だったのが、**自分の感じた不便さや物足りなさを、具体的な指示にすること**でした。

「もっと見やすくして」「分かりやすくして」「面白くして」と言いたくなるのですが、それだけでは、画面のどこをどう変えたいのかまでは伝わりません。

自分でも、最初は「なんとなく見にくい」としか感じていないことがあります。そこから画面を見直して、文字なのか、配置なのか、説明が足りないのかを考える必要がありました。

例えば、今回の調整は次のような形です。

| 最初に感じたこと | 具体的にお願いしたこと |
| --- | --- |
| 画面が見にくい | 小さい文字を大きくして、読みやすくする |
| どこを押せばよいか分かりにくい | 最初の操作説明に、スキルツリーの枠をクリックする様子が分かる画像を入れる |
| 購入できるか分かりにくい | 枠内に「購入可」「強化可」と表示し、実行できないものはグレーアウトする |
| 買えない理由が分からない | GPUの枠内に「サーバーラック不足」など、足りないものを表示する |
| 成長の順番が分かりにくい | 設備の解放順に番号を付け、前提となる設備と矢印でつなぐ |

「操作しているときの画像を出してほしい」というお願いも、どんな操作を、どの画面で見せたいのかまで考える必要があります。

今回は、最初の画面で操作説明を出して、スキルツリーの枠をクリックして購入することが分かるようにしてもらいました。文章だけで操作を説明するよりも、押す場所が見えるほうが伝わりやすいと思ったからです。

スキルツリーの矢印についても、「矢印を見やすくして」だけでなく、枠を小さくしたり、項目の位置を動かしたりしました。購入と強化をタブで分けることも、やり取りしながら決めていった部分です。

こうして並べると単純なお願いに見えるのですが、実際に遊んでいる最中に、違和感の原因を見つけて言葉にするのは意外と難しかったです。

## 作ってもらいながら、自分が欲しいゲームも見えてくる

今回の制作では、最初から完成形を細かく決めていたわけではありません。

まず動くものを作ってもらい、触ってみて気になったところを伝え、直してもらってからまた遊ぶ。その繰り返しでした。

その中で、自分は何を楽しいと感じるのか、どんな説明があると迷わないのか、何を買ったときに成長した感じがするのかも、少しずつ見えてきました。

Codexに実装をお願いできても、「これで遊びたいと思うか」を確かめたり、変えたいところを考えたりする作業は残ります。むしろ、動くものができたことで、その部分を具体的に考える場面が増えた気がします。

今後もこのブログにゲームを追加していきたいので、ゲームごとにファイルを分け、一覧ページから選べる形にも整理しました。[ブラウザゲームの一覧はこちら]({{< ref "games/_index.md" >}})です。

ゲームの大枠ができるまでと、遊んで面白いと感じるまでには、別の大変さがありました。でも、「何か足りない」と思ったものを、言葉にして少しずつ変えていく過程も、自分でゲームを作る面白さなのかもしれません。

まだ調整したいところはありますが、まずは一つ形にできたので、これからも遊びながら手を入れていこうと思います。次回はアクション系のゲームにも挑戦できたらと思います。ではでは。
